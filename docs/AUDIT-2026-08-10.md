### What's wrong (real bugs found by reading code)

#### Bug 1 — Bubble label lies about state on `onFinal`
**File:** `bubble/FlowAccessibilityService.kt:457–469`
**Symptom (user reported):** "text is still shown in the floating pill"
```kotlin
override fun onFinal(text: String) {
    if (text.isBlank()) return
    if (sessionBuffer.isNotEmpty()) sessionBuffer.append(' ')
    sessionBuffer.append(text.trim())
    if (prefs?.bubbleShowText == true) {
        bubbleLabel?.text = BubbleLabelFormatter.finalChunk(sessionBuffer.toString())  // ← ON
    } else {
        setListenChrome(...) // ← still OFF path
    }
}
```
**Reality:** the OFF path **does not toggle** `showText` — it falls back to chrome. Per session `019febd3`, the user wanted **transcript off** by default. The plumbing supports it, but `BubbleLabelFormatter.partial/preview` is only called when `bubbleShowText == true`. So `bubbleShowText` defaults to `false` (FlowPrefs:99) → bubble correctly shows chrome only. **This is "fixed" in code** BUT **the default is silently `false` and the user has no UI to flip it without diving into Settings → Bubble.** Documented, not broken — but the user is reporting "text still shows", which is either: (a) stale build, (b) they toggled it on once and forgot, or (c) the partial path leaks text on Start event. **Check (c):** `onReady` line 491-503 reads `prefs?.bubbleShowText` correctly. So path is fine. → **Real answer: bubble defaults are right; user's complaint is from old APK or the toggle being on. Fix: surface `bubbleShowText` in Home QUICK chips so it's a 1-tap off.**

#### Bug 2 — `setBubbleEmphasis` fights pulse during listening

```kotlin
private fun setBubbleEmphasis(hasField: Boolean) {
    if (listening) return // pulse owns alpha while listening ← OK

```
**Reality:** early return is correct. NOT a bug. → **False alarm on re-read. Skip.**

#### Bug 3 — `applyModeLabel` while `listening = false` after drop 3 corrupts state
**File:** `bubble/FlowAccessibilityService.kt:711–716` and `:677–689`

fun applyPrefsVisual() {

This **does** call `renderIdle()` while still in stale state if user changed bubbleMode mid-listen. Acceptable — only fires when not listening. → NOT broken.

#### Bug 6 — `BubbleLabelFormatter.partial()` cap is 80 chars
**File:** `bubble/BubbleLabelFormatter.kt:12–16`
**Symptom (user reported via Wispr research):** "shapes are bullshit and text is still shown". Cap 80 chars is correct for chrome, but the bubble's actual `TextView` has no `maxLines=1` guard at runtime — long content wraps off-screen.
**Reality:** 80-char cap should prevent this. If user sees text overflow, the bubble view is using WRAP_CONTENT + no width cap. **Check `res/layout/flow_bubble.xml`** (next step). → **Inspect, fix `maxWidth` if needed.**

#### Bug 7 — `BubbleLabelFormatter.idle()` always returns "🎙 Tap to talk", ignores pref
**File:** `bubble/BubbleLabelFormatter.kt:8` + caller `FlowAccessibilityService.renderIdle():677–689`
The Object method is constant. UI bypass for showText uses `applyModeLabel` at line 363, but `renderIdle` still calls `BubbleLabelFormatter.idle()` at the end. **Looks fine** — but if user has `bubbleShowText = false`, the final `BubbleLabelFormatter.idle()` line still wins over the icon-only branch due to the `else` ternary. → **Confirm via real run, likely fine.** → **Defer.**

#### Bug 8 — `ContinuousPolicy.ERROR_*` constants duplicated
**File:** `stt/ContinuousPolicy.kt:40–50`
**Reality:** these mirror `android.speech.SpeechRecognizer.ERROR_*` exactly. YAGNI violation. Use `android.speech.SpeechRecognizer.ERROR_*` directly. **Ponytail cut.** ~12 lines.

#### Bug 9 — `DictationRepository.bumpStats` is per-call (race)
**File:** `data/DictationRepository.kt:70–87`
`statsDao.get()` + `statsDao.upsert()` are not atomic. Two concurrent saves (very rare from one device, but possible from UI "Copy last" + a11y save) → lost update. **Fix:** wrap in `withTransaction { … }`. ~5 lines. **Ponytail `TODO` ceiling.**

#### Bug 10 — `FlowAccessibilityService.commitSessionToField` always re-resolves
**File:** `bubble/FlowAccessibilityService.kt:597–645`
`commitSessionToField` re-resolves via `rootInActiveWindow` but does not call `FieldPolicy.mergeSession` after resolving — the merge happens at line 619, but with the **stale `fieldPrefix` snapshot from listen start**. If user typed during listen, prefix is stale, prefix gets clobbered. → **Race in 4:30→5:30 case while field is being edited.** User said it works on stop, but the bubble session is short and the field prefix could have changed. **Fix:** re-capture field prefix right before commit, but only when no user typing detected (practical). OR drop merge entirely and use cursor-based insert (`ACTION_SET_TEXT` already replaces all; merge is needed only for prefix preservation). Real Wispr behavior: SET_TEXT replaces field text entirely. **So `fieldPrefix` is dead code for SET_TEXT path.** → **Drop `fieldPrefix` capture/merge; SET_TEXT does the right thing.**

#### Bug 11 — `BubbleSettings` does NOT expose `bubbleShowText` toggle visibly
**File:** `ui/MainActivity.kt:920–933`
The toggle exists, labeled "Show speech on bubble". OK on bubble settings page. → **Real bug: Home `keys` module has no toggle for it.** User said it should be 1-tap. → **Add to Home keys card.**

#### Bug 12 — `LayoutPrefs.parseModules` migrates legacy ids but ignores `customize`
**File:** `prefs/LayoutPrefs.kt:35`
Drops legacy `dictionary / snippets / style / settings` silently. Custom drawer extras list = `history, customize`. Old prefs saved with `dictionary,snippets,style,settings,customize` would parse as empty + then default-fill. → **Add a real migration in `OpenFlowDatabase.get`** or accept the silent default. **Defer.**

#### Bug 13 — `SttEngine.startContinuous` calls `beginSession` from main handler but immediate `setListener` call site in `FlowAccessibilityService` happens **inside** `startContinuous`
**File:** `bubble/FlowAccessibilityService.kt:444–516` then `:516` `stt?.startContinuous(lang)`
**Race:** `stt.startContinuous` posts to main handler; listener is set **before** the post runs; listener captures current `sessionBuffer`. On rotation / re-listen, old listener stays attached. **Fix:** `stt.setListener(obj)` AFTER `startContinuous` returns — but the post is async so this still races. **Pragmatic fix:** cancel old listener by setting `stt.setListener(null)` in `stopListening()`, or use `lifecycle` of listener object. → **Fix needed; risky as-is.**

#### Bug 14 — `BubbleSettings` saves `languageTag` to prefs but SttEngine reads it only at `startContinuous`. Mid-session change has no effect.
**File:** `ui/MainActivity.kt:968–976` + `SttEngine.kt:60–62`
**Reality:** `startContinuous(lang)` is called once per session. If user changes lang while listening, no-effect until next session. **Fix:** restart STT on lang change in bubble settings. → **Add bubble restart on pref change.**

#### Bug 15 — `OpenFlowDatabase` version = 3 with `fallbackToDestructiveMigration`
**File:** `data/OpenFlowDatabase.kt:15` + `:34`
**Reality:** drops all user data on schema bump. Acceptable for MVP. → **Defer.**

#### Bug 16 — Tests don't cover the new M3 shell

**Reality:** 24 tests exist; new MainActivity routing + `LayoutPrefs.parseModules` edge cases are uncovered. Critical: every parser/prefs should have a single assert-based demo. → **Add 4 micro-tests:**
- `LayoutPrefs.parseModules("!history,customize")` → history hidden, customize visible
