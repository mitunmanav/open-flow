# Research result

**Status: Partial**

Wispr Flow on Android is a cloud-backed floating dictation bubble over the existing keyboard—not a keyboard replacement—using overlay, Accessibility Service, and mic permissions to insert polished text into focused fields.[S1][S2] Core dictation includes auto punctuation, spoken mark names, filler removal, self-corrections (Backtrack), lists, Dictionary, Snippets, and writing styles; Auto Cleanup’s four levels (None/Light/Medium/High) supersede simple Smart Formatting on/off, while Command Mode and Context Awareness stay desktop-only.[S3][S4][S6][S10][S11] Flow requires internet (no offline STT); Free Android dictation is unlimited, with Pro about $15/mo or $12/yr USD for unlimited across platforms.[S5] A FOSS en-US bubble app can match most of that polish with local rules (as Open Flow already does) plus SpeechRecognizer + AccessibilityService insertion patterns, but freeform semantic rewrite is not achievable without an LLM.[S12][S16][S20][S21]

### Android product model
Wispr Flow sits as a floating Flow Bubble above the system keyboard when a text field is focused; users tap or long-press (push-to-talk) to dictate.[S1][S10] Required grants are Display Over Other Apps, Accessibility Service, and Microphone, with optional battery exemption.[S1] Accessibility is disclosed only for detecting editable fields (to show the bubble), inserting dictated text, detecting keyboard visibility, and limited diagnostics—not for scraping other apps when dictation is inactive.[S2] Desktop activation is hotkey-based; Android uses the bubble, while the core dictation experience is described as the same.[S10]

### Dictation stack: formatting, Backtrack, cleanup, styles
Smart Formatting and Backtrack ship on Android: Smart Formatting is on by default with no Android off-toggle and covers punctuation, lists, and filler cleanup; Backtrack applies self-corrections via triggers such as “actually” / “scratch that” or natural restates (e.g. “coffee at 2 actually 3”).[S3] Launch materials also list auto punctuation from pauses and tone, optional spoken marks (“comma”, “parentheses”), filler “um”/“uh” removal, self-corrections, and numbered lists.[S10] Auto Cleanup under Style offers four levels—None (exact transcript), Light (fillers/grammar), Medium (clarity/conciseness), High (brevity/polish)—replacing simple on/off; the dedicated Auto Cleanup help article was unavailable when checked, and Android Style docs stress tone categories more than naming those four levels on-device.[S6] Style tab options are English-optimized and per-category (Personal: Formal/Casual/Very Casual; Work/Email/Other: Formal/Casual/Excited); Dictionary and voice Snippets are on Android.[S4] AI writing-style prompts (Polish instructions) and auto-cleanup level sync across devices including Android.[S11]

### Spoken punctuation, layout, and style interaction
Flow auto-inserts most punctuation and maps spoken mark names to symbols: period/full stop, comma, question mark, exclamation point, colon, semicolon, dashes, quotes, brackets/braces/parentheses, ellipsis, slash/backslash, and symbols such as @ # $ % & * (e.g. “…exclamation point … period” → “…! ….”).[S7] Layout phrases insert breaks: “new line” / “next line” / “line break” for a line break; “new paragraph” / “start a new paragraph” / “skip a line” for a paragraph break.[S8] Style and app context mainly affect trailing-period stripping—not whether spoken punctuation/edit commands run: trailing periods may be removed by Writing Style rules when appropriate; “!” and “?” are always kept under that rule; Smart Formatting still handles grammar, punctuation, capitalization, and fillers.[S9] Trailing-period policy varies by style/context (e.g. short messaging dictations with no style; Casual shorter any-app; Very Casual any length).[S9][S11]

### Command Mode and desktop-only gaps
Command Mode (highlight text and speak rewrite/transform commands; also “press enter” after paste) is Mac/Windows only and Pro/trial-gated—not on Android.[S4][S11] Context Awareness (app-category style and mid-sentence casing/punctuation from nearby text) is likewise Mac/Windows only.[S11]

### Privacy, connectivity, pricing
Dictation needs an active internet connection; offline transcription is not supported.[S5] Free plan word limits: 2,000/week desktop, 1,000/week iPhone, unlimited on Android; Pro is unlimited dictation across platforms at about $15/user/mo monthly or $12/user/mo annual (USD).[S5]

### Overlay and Accessibility insertion (platform patterns)
Bubble/overlay UIs use `TYPE_APPLICATION_OVERLAY` (requires `SYSTEM_ALERT_WINDOW` / user overlay grant) or `TYPE_ACCESSIBILITY_OVERLAY` from a connected AccessibilityService; `FLAG_NOT_FOCUSABLE` keeps focus on the field under the bubble.[S17] Text insertion: `ACTION_SET_TEXT` replaces node text via `ACTION_ARGUMENT_SET_TEXT_CHARSEQUENCE` and moves the cursor to the end; `ACTION_PASTE` pastes the clipboard; both work only when the node exposes the action and is editable—support is app/node-defined, not universal.[S16]

### SpeechRecognizer architecture
`SpeechRecognizer` is session-based (`startListening` / `stopListening` + `RecognitionListener`), not meant for continuous recognition; calls must run on the main thread with `RECORD_AUDIO`, and callers must `destroy()` when finished; wait for `onResults` or `onError` before starting again.[S12] Offline-prefer STT uses `RecognizerIntent.EXTRA_PREFER_OFFLINE` and/or `SpeechRecognizer.createOnDeviceSpeechRecognizer`—both implementation-dependent.[S13] Partials vs finals: `EXTRA_PARTIAL_RESULTS` enables `onPartialResults`; finals use `onResults`; both expose `RESULTS_RECOGNITION` string lists.[S14] API 33+ `EXTRA_ENABLE_FORMATTING` can format partial/final text (punctuation/capitalization) with latency vs quality strategies; engines may ignore it.[S15]

### FOSS local alternatives (no cloud AI path)
FUTO Voice Input runs STT fully on-device (Whisper / whisper.cpp), integrates via `ACTION_RECOGNIZE_SPEECH` and Voice IME, never saves/sends recordings, and uses the network only for optional model downloads; accuracy levers include model size (larger = more accurate, slower) and personal dictionary (sometimes better disabled).[S18][S23] Sayboard uses Vosk models as a voice keyboard and states it never sends user information; woheller69 Whisper IME downloads a Whisper TFLite model once, then runs offline as IME, RecognitionService, and `RECOGNIZE_SPEECH` (≈30s per recording; English-only vs multilingual model choice).[S19]

### What Open Flow can do locally without an LLM
Open Flow already implements fully local, non-LLM post-processing suited to an en-US bubble app: CleanupPipeline levels None/Light/Medium/High (fillers, repetitions, false starts, list hints, rule brevity); CourseCorrector mid-utterance fixes; VoiceCommands for spoken punctuation/layout/edit; dictionary replace; snippet expand; WritingStyle Formal/Casual/Very casual/Excited/Custom as presentation and user replace rules—not LLM tone rewrite.[S20] Freeform semantic rewrite / cloud Command Mode (“make more concise”) is not true LLM-free FOSS; rule-based cleanup and styles cover deterministic polish only.[S21]

### Realistic local-only product opportunities
Documented still-open local-only opportunities (no cloud AI required) include history export/share, optional notifications, memo audio recorder + transcript, language-pack UX, and later opt-in on-device Whisper—while keeping privacy defaults of no forced account and no cloud STT by default.[S22]
